# Presets (`presets/`)

Name-to-asset resolution for the two effects that ship as bundled files rather than code: color grading and music. Both modules raise on a missing preset or asset instead of falling back to something else, since a broken preset should fail the render loudly, not silently no-op. Variety in the product is meant to come from adding a new LUT or manifest entry, not from new code paths.

## Color (`color.py`)

`lut_path_for(preset)` maps `cinematic`, `vivid`, or `bw` to a `.cube` file under `presets/luts/`, generated by `tools/generate_luts.py` and committed to the repo. `none` returns `None`, meaning no LUT is applied. A `KeyError` if the preset name itself is unknown, and a `FileNotFoundError` if the name is valid but the bundled file is missing, so an asset that silently didn't ship never gets treated as "no grading applied."

## Music (`music.py`)

`resolve_track(track_id)` looks `track_id` up in `music_manifest.json` (a flat map of id to filename plus mood) and resolves it against `assets/music/`. A `user:<src_id>` track, meaning a user-uploaded audio file, never goes through this function at all: the caller (`services/render/`) passes it straight to `compile_plan` as `music_override` instead, since it isn't part of the bundled catalog.

```json
{
  "placeholder-energetic": {"file": "placeholder-energetic.wav", "mood": "energetic"},
  "placeholder-chill": {"file": "placeholder-chill.wav", "mood": "chill"}
}
```

The `mood` field is what the LLM planner sees in its music catalog; the filename never leaks into the prompt.
